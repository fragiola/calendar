---
title: Model and engine
description: The model holds the calendar and runs in plain Node; the engine is one calendar on screen, with its focus, gestures, previews and measurements.
---

Two objects split the work. The **model** is the calendar: its document, its view, its rules and
its layouts, with no DOM. The **engine** is one calendar on screen: it listens to the root
element's pointers and keys, keeps the focus, runs the gestures, previews a drag, measures the
days and tells your app what happened. Both answer the same five verbs, `run`, `can`, `check`,
`get` and `is`.

## The model

What can be known without a screen is the model's: the events, the visible range, the layout of a
month or a week (`model.get("day-grid")`, `model.get("time-grid")`, `model.get("list")`), the
titles as `Intl` parts. A server can navigate it and an assistant can move events with it. Its
clock is injectable, so "today" is the same in a test as in production
([Dates and time zones](/docs/concepts/dates-and-time-zones)).

```ts
import { createCalendarModel } from "@fragiola/calendar";

const model = createCalendarModel(json, {
    now: () => Date.parse("2026-11-26T12:00:00-05:00"),
});
model.run("view.set", { type: "month" });
model.get("visible-range"); // { start: "2026-11-01", end: "2026-12-13" }: six weeks, Sunday first
```

## The engine

`Calendar.Root` creates the engine (`createCalendarEngine(model, options)`) when it mounts (in a
layout effect in React, `onMounted` in Vue, after the first render in Angular), attaches its element and destroys it on unmount. The parts register their elements
with it; you never do. Before it exists (the server render, the first client render) every part
reads its attributes and its layout from the model, so the server's HTML is the client's first
render.

What only a screen has is the engine's: the focused date or event (`engine.get("focused")`), the
drag preview (`engine.get("drag-preview")`), the lanes that fit a day
(`engine.get("max-lanes")`), the reading direction. Its actions move the focus or cancel a
gesture:

<Framework name="react">

```tsx
import { useCalendar } from "@fragiola/calendar-react";

function GoToToday() {
    const { model, engine } = useCalendar();
    return (
        <button
            type="button"
            onClick={() => engine.run("focus", { date: model.get("today") })}
        >
            Focus today
        </button>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="go-to-today.vue"
<script setup lang="ts">
import { useCalendar } from "@fragiola/calendar-vue";

const { model, engine } = useCalendar();
</script>

<template>
    <button type="button" @click="engine.run('focus', { date: model.get('today') })">
        Focus today
    </button>
</template>
```

</Framework>

<Framework name="angular">

```ts title="go-to-today.ts"
import { Component } from "@angular/core";
import { injectCalendar } from "@fragiola/calendar-angular";

@Component({
    selector: "app-go-to-today",
    template: `
        <button type="button" (click)="calendar.engine.run('focus', { date: calendar.model().get('today') })">
            Focus today
        </button>
    `,
})
export class GoToToday {
    protected readonly calendar = injectCalendar();
}
```

</Framework>

`useCalendar` gives both anywhere inside the root. The engine it returns is there from the first
render (from `setup` in Vue, `injectCalendar()` in Angular): before the root is mounted an action is refused and a read is empty.

## What the engine tells you

The engine's events are the root's: an event click (a tap, or Enter on an event), a date click (a
day or a slot), a more click (a "+N more" link), a today change (midnight), an announcement (data
for your live region), and with their features a selection, an event drop and an external drop. A
drop has already run its command when you hear it; a selection is a range for your app to act on.

<Framework name="react">

They are the root's callbacks: `onEventClick`, `onDateClick`, `onMoreClick`, `onTodayChange`,
`onAnnounce`, `onSelect`, `onEventDrop` and `onExternalDrop`.

```tsx
<Calendar.Root
    model={model}
    onEventClick={({ eventId }) => openEditor(eventId)}
    onDateClick={({ date, time }) => console.log("pressed", date, time)}
>
    {/* … */}
</Calendar.Root>
```

</Framework>

<Framework name="vue">

They are the root's listeners: `@event-click`, `@date-click`, `@more-click`, `@today-change`,
`@announce`, `@select`, `@event-drop` and `@external-drop` (a feature's listener is a type error
on a root typed without it, `typedCalendar<Types, typeof features>()`).

```vue
<Calendar.Root
    :model="model"
    @event-click="({ eventId }) => openEditor(eventId)"
    @date-click="({ date, time }) => console.log('pressed', date, time)"
>
    <!-- … -->
</Calendar.Root>
```

</Framework>

<Framework name="angular">

They are the root's outputs: `(eventClick)`, `(dateClick)`, `(moreClick)`, `(todayChange)`,
`(announce)`, and a feature's from its directive on the root: `(rangeSelect)` with
`calendarSelection`, `(eventDrop)` with `calendarDragAndDrop`, `(externalDrop)` with
`calendarExternalDrop`.

```html
<div
    [calendarRoot]="model"
    (eventClick)="openEditor($event.eventId)"
    (dateClick)="pressed($event.date, $event.time)"
>
    <!-- … -->
</div>
```

</Framework>

## Outside the root

A toolbar or a test outside the root reaches both through a calendar ref, `useCalendarRef` in a
component or `createCalendarRef` in a module:

<Framework name="react">

```tsx
import { Calendar, useCalendarRef } from "@fragiola/calendar-react";

function Planner() {
    const calendar = useCalendarRef();
    return (
        <>
            <button type="button" onClick={() => calendar.current?.model.run("view.today", {})}>
                Today
            </button>
            <Calendar.Root calendarRef={calendar} defaultEvents={[]}>
                {/* … */}
            </Calendar.Root>
        </>
    );
}
```

</Framework>

<Framework name="vue">

A calendar ref is not a Vue ref: the template passes it as it is and reads `calendar.value`, which
is reactive (`null` until the root mounts).

```vue title="planner.vue"
<script setup lang="ts">
import { Calendar, useCalendarRef } from "@fragiola/calendar-vue";

const calendar = useCalendarRef();
</script>

<template>
    <button type="button" @click="calendar.value?.model.run('view.today', {})">Today</button>
    <Calendar.Root :calendar-ref="calendar" :default-events="[]">
        <!-- … -->
    </Calendar.Root>
</template>
```

</Framework>

<Framework name="angular">

A calendar ref's `current` is a signal's value: a template or a `computed` that reads it follows
the root (`null` until it renders).

```ts title="planner.ts"
import { Component } from "@angular/core";
import { CALENDAR, injectCalendarRef } from "@fragiola/calendar-angular";

@Component({
    selector: "app-planner",
    imports: [CALENDAR],
    template: `
        <button type="button" (click)="calendar.current?.model.run('view.today', {})">Today</button>
        <div calendarRoot [calendarRef]="calendar" [defaultEvents]="[]">
            <!-- … -->
        </div>
    `,
})
export class Planner {
    readonly calendar = injectCalendarRef();
}
```

</Framework>
