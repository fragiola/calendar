title: Installation
description: Install the React or the Vue package, which brings the core and re-exports it, and import each opt-in feature from its own entry.
---

Each framework has one package, which depends on the core `@fragiola/calendar` (at the exact same
version) and re-exports all of it, so an app installs and imports one package: the `Calendar.*`
primitives, the hooks or composables, the model and every core type.

## Install the package

<Framework name="react">

A React app installs `@fragiola/calendar-react`:

<Tabs items={["pnpm", "npm", "yarn"]}>
    <Tab value="pnpm">
        ```sh
        pnpm add @fragiola/calendar-react
        ```
    </Tab>
    <Tab value="npm">
        ```sh
        npm install @fragiola/calendar-react
        ```
    </Tab>
    <Tab value="yarn">
        ```sh
        yarn add @fragiola/calendar-react
        ```
    </Tab>
</Tabs>

`react` and `react-dom` (`^19`) are peer dependencies: your app provides them.

</Framework>

<Framework name="vue">

A Vue app installs `@fragiola/calendar-vue`:

<Tabs items={["pnpm", "npm", "yarn"]}>
    <Tab value="pnpm">
        ```sh
        pnpm add @fragiola/calendar-vue
        ```
    </Tab>
    <Tab value="npm">
        ```sh
        npm install @fragiola/calendar-vue
        ```
    </Tab>
    <Tab value="yarn">
        ```sh
        yarn add @fragiola/calendar-vue
        ```
    </Tab>
</Tabs>

`vue` (`^3.5`) is the peer dependency: your app provides it. The primitives are render functions,
so no compiler plugin is needed beyond your app's own.

</Framework>

Each package has no other runtime dependency, and ships ES modules only, with their type
declarations.

## Import the parts

<Framework name="react">

The primitives are one namespace, `Calendar`; the hooks, the model and every core type are named
exports of the same package:

```tsx
import {
    Calendar,
    createCalendarModel,
    useCalendarTitle,
    type CalendarEventJson,
} from "@fragiola/calendar-react";
```

</Framework>

<Framework name="vue">

The primitives are one namespace, `Calendar`, and `typedCalendar<Types, typeof features>()` gives
the same namespace typed by your registry and features (what React writes as type arguments, a
template cannot). The composables, the model and every core type are named exports of the same
package:

```ts
import {
    Calendar,
    createCalendarModel,
    typedCalendar,
    useCalendarTitle,
    type CalendarEventJson,
} from "@fragiola/calendar-vue";
```

The pages of the API reference show the React props; [Vue primitives](/docs/api/vue) maps each
onto Vue (kebab-case props, scoped slots for children functions, listeners for callbacks,
`v-model` for controlled values).

</Framework>

## Import a feature from its entry

What not every calendar needs is an opt-in feature, each on its own entry, so a calendar that
does not drag never ships the drag code. An entry exports the feature's factory, its parts and
its hooks (composables in Vue). The entries are the same in both packages
(`@fragiola/calendar-vue/selection`, …):

| entry | factory | parts and hooks |
| --- | --- | --- |
| `@fragiola/calendar-react/selection` | `selection()` | `Selection`, `useSelection` |
| `@fragiola/calendar-react/drag-and-drop` | `dragAndDrop()` | `DragPreview`, `useDragPreview` |
| `@fragiola/calendar-react/resize` | `resize()` | `ResizeHandle`, `DragPreview`, `useDragPreview` |
| `@fragiola/calendar-react/external-drop` | `externalDrop()` | |
| `@fragiola/calendar-react/now-indicator` | `nowIndicator()` | `NowIndicator`, `useNowPosition` |
| `@fragiola/calendar-react/constraints` | `constraints()` | `BusinessHours`, `useBusinessHours` |
| `@fragiola/calendar-react/recurrence` | `recurrence()` | |
| `@fragiola/calendar-react/event-sources` | `eventSources()` | |

<Framework name="react">

```tsx
import { dragAndDrop, DragPreview } from "@fragiola/calendar-react/drag-and-drop";
import { selection } from "@fragiola/calendar-react/selection";

const features = [selection(), dragAndDrop()] as const;
```

</Framework>

<Framework name="vue">

```ts
import { dragAndDrop, DragPreview } from "@fragiola/calendar-vue/drag-and-drop";
import { selection } from "@fragiola/calendar-vue/selection";

const features = [selection(), dragAndDrop()] as const;
```

</Framework>

[Features](/docs/concepts/features) explains how a model takes them.

## Without a framework

The core is published on its own as `@fragiola/calendar`, for code that renders nothing: handling
calendar JSON on a server, a script or a test that runs no framework.

```sh
pnpm add @fragiola/calendar
```

```ts
import { createCalendarModel, type CalendarDocument } from "@fragiola/calendar";
```

An app never needs it: it comes with its framework's package.

## Using it beside Fragiola Primitives

<Framework name="react">

`@fragiola/primitives-react` also exports a `Calendar`: its date picker. In a file that uses
both, alias one of them:

```tsx
import { Calendar } from "@fragiola/calendar-react";
import { Calendar as DatePicker } from "@fragiola/primitives-react";
```

</Framework>

<Framework name="vue">

`@fragiola/primitives-vue` also exports a `Calendar`: its date picker. In a file that uses both,
alias one of them:

```ts
import { Calendar } from "@fragiola/calendar-vue";
import { Calendar as DatePicker } from "@fragiola/primitives-vue";
```

</Framework>

A date the date picker gives (`{ year, month, day }`) is the calendar's `PlainDate` too, so it
goes to `view.go-to` with no conversion:

```ts
model.run("view.go-to", { date: { year: 2026, month: 11, day: 26 } });
```

The [team planner](/examples/team-planner) example puts the two side by side.
