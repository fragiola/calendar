Every change to a calendar is a command: `model.run(name, payload)` from code, or
`model.dispatch({ command, payload })` for untrusted JSON. A command never throws on bad
input: it returns `{ ok: true, value }` or `{ ok: false, error: { code, message, path } }`
with the codes `unknown_command`, `invalid_payload`, `not_found`, `refused`, `vetoed`,
`queued` and `middleware_error`. `model.get("commands")` lists the same commands with their
JSON Schemas, ready to become an assistant's tools.

## Batches

### `batch`

Run several commands as one step: they apply in order, each seeing the result of the ones before it, and either all of them apply (one event, one undo step) or none does (the first failure is returned, at its path in `commands`).

**Payload**

| field | type | required | description |
| --- | --- | --- | --- |
| `commands` | `object[]` | yes | the commands, in order |

**Result**

| field | type | required | description |
| --- | --- | --- | --- |
| `results` | `JSON[]` | yes | each command's value, in order |

It may run as a transient step (`{ transient: true }`).

```ts
model.run("batch", {"commands":[{"command":"view.set","payload":{"type":"week"}},{"command":"view.next","payload":{}}]});
model.dispatch({"command":"batch","payload":{"commands":[{"command":"view.set","payload":{"type":"week"}},{"command":"view.next","payload":{}}]}});
```
